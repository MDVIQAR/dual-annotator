Raw image — image before annotation
Annotated — polygon and shape masks drawn over the image
CO
Concentric Mode — Ring Targets

Specialised mode for annotating concentric circular targets (e.g. coin edges, ring targets). Uses an inner-wins renderer — each shape you draw has all previously-drawn shapes automatically cut out of its fill, creating distinct nested zones.

Raw image — before annotation
Annotated — three nested zones, each a different class

How to draw concentric zones

⚠️
Switch to Concentric mode first — The mode selector is at the top of the canvas. Concentric mode must be active before drawing; shapes drawn in YOLO or UNet mode will not render as nested zones.
1
Draw the innermost shape

Select a shape tool (circle, polygon, ellipse — any type) and draw the smallest central shape first. Assign it a class. This becomes the core zone and fills completely.

2
Draw the middle shape

Draw the next ring around the first shape. The renderer automatically subtracts the inner shape's area from this fill — only the region between the two boundaries is coloured. Assign it a different class.

3
Draw the outermost shape

Draw the largest outer boundary last. All previously-drawn shapes are subtracted from its fill, leaving only the outermost ring region coloured. Continue adding more shapes outward for as many zones as needed.

💡
Draw order is everything — Innermost shape first, outermost last. The renderer uses draw order (not size) to decide which shape cuts into which.
⚠️
Export as Concentric Masks only — When exporting, select Concentric Masks in the Export dialog. Exporting concentric annotations as YOLO, COCO, VOC, or UNet Masks will not capture the zone structure correctly.

Hollow / Inner Cutout

Any existing shape can have an inner cutout punched through it — making it hollow. This is used when the region of interest is a ring or frame shape that the built-in Frame/Donut tools don't cover exactly.

Works on: Box, Circle, Ellipse, Polygon, Bezier Polygon.

1
Select the shape

Click the shape you want to make hollow. It will highlight in yellow when selected.

2
Right-click → Add Inner Cutout

Right-click the selected shape to open the context menu and choose Add Inner Cutout. A thickness dialog will appear near the shape.

3
Set the offset in the thickness dialog

Drag the slider or type a pixel value. A yellow dashed preview shows the inner boundary in real time. Choose Inward (shrink from outer edge) or Outward (expand from a smaller inner), then click Apply.

Inward — inner boundary shrinks from the outer edge inward
Outward — outer boundary expands from a smaller inner shape outward
💡
The cutout renders as a true hole — The inner region is subtracted from the filled shape using QPainterPath, so it genuinely appears transparent. The exported mask also reflects the hollow area.
Auto-Detect

Template Matching

Template Matching uses OpenCV to scan the current image and automatically place bounding boxes around regions that look like an existing annotation. It's ideal for images with many repeated objects of the same shape and class.

Full workflow — right-click a shape → Template Matching… → Run Detection

How to use

1
Draw at least one annotation

Annotate one instance of the object you want to find — any shape type works as a template source.

2
Right-click the shape → Template Matching…

Right-click the annotation on the canvas and choose Template Matching…. The panel opens and the Templates counter updates to show the shape added.

3
Adjust the sliders (optional)

Threshold — how closely a region must match the template (default 0.70). Lower it to catch more matches; raise it to reduce false positives.
NMS — Non-Maximum Suppression overlap tolerance (default 0.85). Lower values merge detections that are closer together.

4
Click ▶ Run Detection

The engine scans the full image. New bounding boxes are placed for every match and the Status bar shows New: X · Skipped: X · Total: X. Existing annotations are never duplicated — the detector skips any region already covered by a shape.

Panel overview

Templates

Lists the number and type of shapes added as templates. Click Clear Templates to start fresh.

Live Updates

Enable the Live updates checkbox so detection re-runs automatically 400 ms after every slider adjustment — no need to click Run each time.

💡
Class inheritance — Detected shapes inherit the class of the template shape. If no class is set on the template, the currently active class is used instead.

The Collaboration feature lets a team annotate the same project simultaneously over a local network. One person hosts a session, shares a Project ID, and everyone else joins. No internet connection is needed — it runs entirely on your LAN using Python's standard library networking.

  • 2
    Starts the server to generate a Project ID
  • 3
    Shares the Project ID with the team

    Monitors connected annotators and live activity

  • 1

  • 2

  • 3

Overview

What is RAW → PNG?

Thermal and specialized cameras output raw binary files (.raw, .tif, .tiff) that standard image viewers cannot open. The RAW → PNG tab batch-converts entire folders of these files into standard 8-bit PNGs in seconds using multi-threaded NumPy processing — ready to be annotated immediately after.

You can preview any image live, draw a crop region, choose a colormap, and adjust normalization before converting the entire batch.

Full RAW → PNG interface — Left panel: directories, conversion settings, and PNG gallery. Right panel: real-time preview canvas where you can inspect and crop images before converting the whole batch.
Step-by-Step Guide

Step 1 — Select Input Folder

Click Browse next to the Input field and select the folder containing your raw thermal files. The app accepts .raw, .tif, .tiff, .png, and .dcm files by default — editable in the Extensions field.

Once selected, the output folder is automatically set to a converted_pngs/ subfolder inside your input directory.

Input folder selected — The input path is set and the output folder is automatically created as a converted_pngs/ subfolder inside it. The file count shown reflects how many matching files were found.

Step 2 — Preview Loads Automatically

As soon as you select a folder, the first file loads into the preview canvas on the right. The preview updates live whenever you change the Colormap or Normalization dropdowns — no need to re-select the folder.

Live preview canvas — The first image in the folder loads automatically. Changing the Colormap or Normalization dropdown instantly re-renders the preview so you can compare settings before committing to a full batch conversion.

Step 3 — Draw Crop (ROI)

If you only want a specific region of each image, left-click and drag on the preview canvas to draw a green crop rectangle. This Region of Interest is applied to every file in the batch during conversion.

Right-click → reset crop Scroll → zoom preview Middle-click drag → pan Double-click → fit to screen
Drawing a Region of Interest (ROI) — Left-click and drag on the canvas to draw the green crop rectangle. Every file in the batch will be cropped to this region during conversion. Right-click anywhere on the canvas to reset back to full image.

Step 4 — Configure Settings

Before converting, set the three settings in the left panel:

A
Camera Model

Tells the app the correct image resolution for reading binary raw data. Use Auto-Detect if unsure — it matches file size to known resolutions.

B
Colormap

The color gradient applied over the grayscale thermal data. C++ Original matches the legacy software palette exactly. See Colormaps for a visual comparison.

C
Normalization

Controls how 16-bit temperature values are scaled into the 0–255 range. See Normalization Modes for details.

Conversion settings panel — Set the Camera Model (resolution profile for reading binary data), Colormap (color gradient applied to thermal intensity), and Normalization mode before running the batch. The Extensions field controls which file types are picked up from the input folder.

Step 5 — Convert

Click the green ▶ Convert button. The progress bar fills as each file is processed and the console log shows each file's status in real-time.

Click ⏹ Cancel at any time to stop — already converted files are kept.

Batch conversion in progress — The progress bar fills file by file while the console log prints each filename and its status. Hit Cancel at any time to stop early; files already converted are saved and won't be lost.

Step 6 — PNG Gallery

Colormaps

A colormap remaps grayscale temperature intensity into a color gradient — making it easier to distinguish hot and cold regions visually. The same raw image looks very different under each colormap. Pick the one that makes defects or regions of interest most visible for your use case.

C++ Original
Pixel-perfect match to the legacy COLOUR TOOL software. Uses a custom 433-entry palette. Best for consistency with older exports.
Inferno
Dark purple to bright yellow. Best general-purpose thermal colormap — high contrast and perceptually uniform.
Viridis
Dark blue to yellow. Colorblind-friendly with uniform contrast throughout the full range.
Plasma
Rich purple to bright yellow. Similar to Inferno with a warmer mid-range tone.
Magma
Deep black to white-yellow. High contrast at extremes — useful for spotting anomalies.
Jet
Classic blue-to-red rainbow. Very common but can falsely emphasize noise — use with caution.
None (Grayscale)
Raw heat intensity as pure black-to-white. No color processing — closest to the original sensor data.

Normalization Modes

Normalization controls how 16-bit values (0–65535) are compressed into 8-bit range (0–255) before the colormap is applied. Different modes handle sensor noise, dead pixels, and contrast very differently.

⚠️
Normalization does not apply when using C++ Original colormap. The C++ Original palette uses a fixed 433-entry lookup table that directly maps raw 16-bit values to specific colours — bypassing the normalization step entirely. If you need normalization to take effect, switch to any other colormap (Inferno, Viridis, Jet, etc.).
Original
Masked min-max that ignores zero-valued (dead) pixels. Maps the coldest valid pixel to black and hottest to white. Best general-purpose mode.
1st–99th Percentile (Robust Contrast)
Cuts off the extreme top and bottom 1% of pixel values before scaling. Hides broken dead sensor pixels and thermal outliers that would otherwise crush contrast.
Min-Max (Auto Contrast)
Stretches the absolute coldest pixel to pure black and absolute hottest to pure white. Maximum contrast but sensitive to single outlier pixels.
Absolute (Divide by Max)
Divides each pixel by the theoretical maximum (65535). Retains the literal heat value ratio but often appears very dark unless the sensor uses the full 16-bit range.

Geometric

↔ Horizontal / Vertical Flip
Mirrors the image left-right or top-bottom.
e.g. Coins, screws, bolts — objects with no preferred orientation.
↻ Rotation
Rotates the image by a random angle up to the configured limit.
e.g. Camera mounted at a fixed angle that may shift slightly between setups.
⬜ Random Crop
Crops a random sub-region of the image (set as % of original size).
e.g. Prevent the model from relying on objects always being centred in frame.
⤡ Scale / Resize
Randomly enlarges or shrinks the image within a configured scale range.
e.g. Objects appearing at different distances from a fixed camera.
➤ Translation / Shift
Shifts the image along x and/or y axes, changing apparent object position.
e.g. Camera not perfectly aligned to the target — slight positional drift.
◱ Shearing
Slants the geometry along one axis, creating a parallelogram-like distortion.
e.g. Parts on a conveyor viewed at a slight angle from the side.
⬡ Perspective Warp
Applies a projective transform simulating a camera looking from a different angle.
e.g. Camera mounted slightly off-axis or at an angle to the subject.
〰 Elastic Distortion
Applies local pixel displacements using a random field, warping the image locally.
e.g. Flexible or deformable objects — cloth, soft packaging, organic shapes.
⬛ Padding / Reflection
Adds a reflected border around the image, expanding the canvas size.
e.g. Objects near the frame edge that would otherwise be partially cropped.
⊞ Grid Distortion
Warps the image using a grid of moveable control points, creating mesh-like distortion.
e.g. Simulate lens barrel/pincushion distortion from wide-angle cameras.

Photometric

☀ Brightness / Contrast
Adds an intensity offset (brightness) or scales around the mean (contrast).
e.g. Changing ambient light throughout the day or between shifts.
🎨 Saturation / Hue Shift
Adjusts colour vividness (saturation) or rotates all hue values globally.
e.g. Objects lit by different light temperatures — LED vs fluorescent vs daylight.
⚡ Gaussian Noise
Adds random per-pixel noise sampled from a Gaussian distribution.
e.g. Low-light images with high camera ISO — noisy sensor output.
🌫 Gaussian Blur
Convolves with a Gaussian kernel, softening edges and reducing fine detail.
e.g. Objects slightly out of focus or motion blur from camera shake.
⬜ Grayscale
Converts the image to single-channel luminance, output still has 3 channels.
e.g. Training on monochrome camera feeds or IR-only setups.
🌈 Color Jitter
Applies brightness, contrast, and saturation changes together in one pass.
e.g. Mixed or unpredictable lighting environments — indoor + natural light.
◑ Gamma Correction
Applies a power-law transform to pixel intensities, brightening or darkening non-linearly.
e.g. Cameras with different gamma settings or auto-exposure compensation.
🔀 Channel Shuffle
Randomly permutes the order of R, G, B channels.
e.g. Prevent the model from over-relying on a single colour channel for detection.
✂ Cutout / Erasing
Fills random rectangular patches in the image with zero (black).
e.g. Partially occluded objects — items partially hidden behind other objects.
📷 JPEG Compression
Re-encodes with lossy JPEG at a random quality level, introducing block artifacts.
e.g. Images from compressed video streams, surveillance cameras, or low-quality feeds.

The Registry tab reads this file to display version details and power the Compare view.

⚠️
Do not edit or delete this file. All writes are atomic — data is written to a .tmp file first, then moved into place. If the file becomes corrupted, the version will show as "unknown" in the Registry.

Top-level fields

version_id
Auto-generated ID — version number + date + time of the run.
e.g. "v3_2026-05-21_14-11"
model_type
Which model type was trained.
"yolo" or "unet"
status
Current state of the run. Updated live — starts as "training", ends as one of the terminal states.
"training" → "completed" / "crashed" / "cancelled" / "partial"
sync_complete
Set to true as the very last write after a completed or partial run — signals to teammates that Google Drive has fully synced this version.
false while training or if crashed
annotator
Name of the person who started the run — taken from the Run Info section.
e.g. "Alice"
commit_message
The short description you typed before starting training — shown in italic in the Registry detail view.
e.g. "increased batch size, added flip aug"
started_at / finished_at
ISO timestamps for when the run started and when it ended. finished_at is null while training is active.
e.g. "2026-05-21T14:11:03"
project / project_name / project_id / variant / camera
The full hierarchy key and its individual parts — mirrors the cascading filter in the Registry tab.
e.g. project: "unet/SnipeX/SLXCAP/CRC/cam0"

What is the Registry?

The Registry is DualAnnotator's model version database. Every time you train a model — whether it completes, crashes, or is cancelled — a record is automatically written to Google Drive. The Registry tab lets you browse all those records, inspect their training details, compare two versions side-by-side, and take actions like re-exporting to ONNX or cloning a run to retrain.

Automatic
Every training run creates a version record — no manual save needed. Completed, crashed, and cancelled runs are all tracked.
Structured
Records are organised by Model Type → Project → ID → Variant → Camera. The cascading filter drills down to exactly the run you want.
Comparable
Select any two versions and switch to Compare mode for a side-by-side diff of dataset, hyperparameters, and all metrics with colour-coded winners.
Registry tab — left panel (filter + version cards) and right panel (version detail)
⚠️
Google Drive required. The Registry reads from and writes to the Google Drive folder set in Settings. If that path is not configured, the left panel shows a warning and no versions are listed.

Coin Rotator

What It Does

The Coin Rotator tab solves a common problem in coin datasets: images are captured at random orientations, so the year text points in all different directions. Before training a model, all coins should face the same way.

The process is two phases:

Phase 1 — Manual Reference
Pick any one coin from the folder. Use the rotation slider to turn it until the year text faces upward. Confirm it — this becomes the reference image that every other coin will be aligned to.
Only needs to be done once per batch.
Phase 2 — Auto Batch Alignment
The app uses SIFT feature matching + FLANN + RANSAC to automatically detect the rotation offset for every other coin in the folder and warp each one to match the reference orientation.
Runs in a background thread — progress shown live.
Left: Phase 1 manual rotation panel  ·  Right: Phase 2 batch matching panel

Pipeline Info

The Pipeline box in Phase 2 shows the exact settings the batch runner uses. These are fixed — no need to configure them.

Detector — SIFT
Extracts up to 8 000 keypoints per image using Scale-Invariant Feature Transform. Falls back to ORB automatically if SIFT is unavailable.
SIFT is robust to scale and rotation — well-suited to circular coin surfaces.
Preprocessing
Each image is converted to grayscale → median blur (removes noise) → adaptive threshold (sharpens edges). This helps SIFT find stable features across different coin finishes.
Runs on both the reference and every target coin before matching.
FLANN Matcher — Lowe Ratio 0.70
Fast Library for Approximate Nearest Neighbours finds candidate feature pairs. Lowe's ratio test (0.70) filters out ambiguous matches — only confident pairs survive.
Lower ratio = fewer but more reliable matches.
Rotation Search — 8 Candidates
Because coins are circular and features repeat, the matcher tries 8 pre-rotation angles (0°, 45°, 90°, 135°, 180°, 225°, 270°, 315°) and keeps the candidate with the most inliers.
This handles coins that are upside-down or 90° off before feature matching.
RANSAC — estimateAffinePartial2D
Estimates a rigid 2D affine transform (rotation + scale + translation) using RANSAC to reject outlier matches. Threshold: 5 px, up to 5 000 iterations, 99% confidence.
Requires ≥ 6 inliers and ≥ 10% inlier ratio to accept the transform.
warpAffine — Direct Warp
The estimated affine matrix is applied directly to the original (colour) coin image, warping it to match the reference orientation and size exactly.
Output images are the same resolution as the reference coin.

Run & Results

The batch starts automatically once you confirm the reference. Everything runs in the background — the UI stays responsive.

1
Progress Bar & Status

A progress bar fills as each coin is processed. The status label below it shows the current filename and position (e.g. Processing 42 / 120 — coin_042.bmp).

2
Live Log

The log console streams a line for every coin: [✓] for successful alignments (shows keypoint count, good matches, inliers, inlier ratio) and [✗] for skipped coins with the reason.

3
Completion Dialog

When the batch finishes, a dialog shows the final count — how many coins were aligned (✓) and how many were skipped (✗). A rotation_log.json is saved in the output folder with the full per-coin record for review.

Understanding the log

[✓] Aligned
Coin was successfully matched and warped to the reference. Output is saved to the output folder with the same filename.
kp=4821  good=34  inliers=22/34  (65%)
kp — keypoints found
good — matches after ratio test
inliers/good — RANSAC inliers
% — inlier ratio
[✗] Skipped
Coin could not be reliably aligned. The reason is printed inline. Skipped files are not copied to the output folder.
Common reasons:
· good=3 — below Min Good Matches
· inlier ratio 0.08 < 0.10 threshold
· No valid affine transform found
Lower Min Good Matches if too many coins are being skipped.
